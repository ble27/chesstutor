## Scope and implementation

Implements [plan.md](../../plan.md) S3 and [PRD](../PRD.md) sections 6, 8–10.
The user confirmed runner/fake-UCI, owned HTTP, real PostgreSQL/Redis recovery,
and browser progress/cancel/retry TDD seams before implementation.

- Pinned Stockfish 17.1 installation verifies archive and binary checksums,
  rejects archive links, preserves license/source/embedded-NNUE provenance, and
  probes required UCI capabilities before worker readiness. No binaries tracked.
- Quick uses 100 ms/MultiPV 2 plus 100 ms played-root search; Deep uses
  750 ms/MultiPV 3 plus 750 ms played-root search. Threads 1, Hash 128 MiB;
  deadlines 90/540 seconds include engine startup. Every PV is legally replayed.
  Full setup/history, White/mover POV, separate mate/cp values, WDL, exact loss
  boundary comparisons, claimable draws and automatic results are preserved.
- PostgreSQL jobs and evidence commit each completed ply atomically. Durable
  dispatch intent survives Redis failures; reconciliation handles lost dispatch,
  expired workers, one recovery, token fencing and original deadlines. Snapshot
  reads keep evidence and progress consistent. Alembic 0002 is reversible.
- Signed anonymous sessions, trusted Origin checks, ownership, 4 KiB submission
  bounds, rolling quotas (5 Quick/2 Deep/session and configurable 20/IP hourly),
  one active/session, 50 queued and two running precede engine submission.
  Completed cache hits are free; cached Deep remains Deep. Active jobs stay
  private. Queue names separate exact executable builds.
- Runtime-validated create/read/cancel contracts and 1–5 second abortable polling
  drive Quick/Deep, progress, cancel/retry, quota/outage/partial feedback and legal
  SAN alternatives at the selected move's pre-move root. Replay selection and
  orientation survive polling. Mate and White evaluations are explicit.
- Compose installs the verified Linux x86-64 engine in two bounded workers.
  The native installer supports macOS ARM64 and Linux x86-64. General readiness
  remains database/Redis; submission separately checks verified worker readiness.

Classification, badges, summaries and coaching remain S4/S5. No dependency added.
No mandatory function-length exception introduced.

## Test-first and defect evidence

Meaningful initial failures covered missing analysis routes, budgets/POV/history,
legal PVs, durable jobs/recovery, owned cancellation and browser lifecycle. Focused
checks passed after each implementation slice. Additional regressions caught:

- A hung UCI analysis-start handshake ignored checkpoints: bounded polling now
  checks cancellation/deadline during handshake as well as during search.
- Float subtraction misclassified exactly 0.02 as unstable: WDL comparisons use
  exact fractions before converting persisted loss to a float.
- Compose startup rejected a valid PID 1 worker parent. The actual container
  reproduction and a failing launcher test confirmed it; only a changed parent
  now signals an exit during Linux parent-death registration. Race rejection is
  retained and tested. Both workers subsequently passed startup readiness.
- A real Linux job exposed an overly tight 512 MiB virtual-address limit. The
  pinned engine measured 666,868 KiB virtual / 374,620 KiB resident with Hash 128.
  The launcher now permits 1 GiB virtual address space; the worker container
  retains its 768 MiB memory cap. Readiness now performs a bounded legal search
  and requires WDL, catching allocation failures before accepting submissions.
  The readiness regression failed before that fix and passed afterward.

Integration tests use a disposable database so the live API reconciler cannot
consume fixture jobs. Migration rollback/reapply never touches application data.
