Date: 2026-11-02. Status: implemented; full automated gate passed; manual acceptance pending.

## Delivered scope

- Small `react-chessboard@5.12.1` adapter, pinned in the npm lockfile, with original
  board colors, read-only pieces, no animation, and last-move outlines. Preserved
  the MIT notice and attributed the default Cburnett artwork under CC BY-SA 3.0.
- Replay selects the existing imported FEN/SAN/UCI sequence directly. No backend
  chess rules, API contracts, or persistence schema changed. No migration is
  needed. Re-import/discovery endpoints retain their S1 behavior.
- First/previous/next/last controls, clickable paired moves, full-move numbering
  from each pre-move FEN (including Black-to-move setups), and board flip that
  preserves selection. A new game/version resets replay. Selection scrolls only
  the move list, keeping the board in place.
- Focused-region Arrow/Home/End handling, endpoint bounds, modifier/typing
  exclusions, visible focus, live position/orientation announcements, and an
  expandable occupied-square table plus exact FEN. The graphic is inert because
  the board library's disabled drag elements otherwise remain tabbable.
- Desktop 2:1 workspace with board/controls/moves on the left and explicitly
  unavailable engine/coaching panel skeletons on the right; stacked tablet/mobile
  panels. Board stays square and page overflow is checked at five widths.
- Frontend network validation now checks display FEN syntax and required move
  notation before rendering. It does not attempt to validate chess legality,
  which remains server-owned. FEN counters must be safe JavaScript integers.

## Test-first evidence

The user confirmed the existing Python importer, public React replay component,
and browser journey seams before new tests were written. Used the implement and
TDD skills; tests assert behavior at those interfaces and fake only HTTP.

- Initial navigation test failed because Replay did not exist, then passed with
  bounded controls and synchronized move selection.
- Black-to-move test failed on incorrect White/Black labels and full-move numbers,
  then passed after pairing from pre-move FENs.
- Board/flip test failed because the board was absent, then passed with the real
  rendering adapter and independent orientation state.
- Focused keyboard test failed because the replay region was not focusable,
  then passed with scoped key handling. Text-position test first failed on the
  missing announcement/table, then passed after adding readable alternatives.
- Fixture-backed browser import first failed because replay was not connected to
  discovery, then passed after workspace integration. The initial sandbox attempt
  could not bind port 5174; browser checks ran with approved local access.
- Invalid FEN and missing-UCI browser cases first reached the UI instead of an
  error; both passed after boundary validation.
- Longer move-list test failed because the selected last move was clipped, then
  passed after scrolling the list to the selected move.
- Python exact-position tests passed immediately against existing importer
  behavior; no artificial backend failure or redundant implementation was added.

Eight synthetic fixtures cover castling both sides, en passant, promotion,
underpromotion, mate, stalemate/draw, Black-to-move setup, and a longer legal
opening. The seven special-case FEN/SAN/UCI sequences were authored as literal
expectations. The longer opening was authored for scrolling and its stored
sequence prepared with the existing importer. Every position is compared to the
importer output and to the browser's rendered piece placement forward/backward.
No live Chess.com or paid service is used.
