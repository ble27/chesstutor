# S1 — Public game discovery and safe import

Date: 2026-11-02. Status: complete; all required local gates passed.
Sprint 2 has not begun. Remote CI and optional live PubAPI smoke have not run.

## Delivered scope

- Username normalization and allowlisted archive paths; newest month selection,
  metadata, exact opponent/color/time-class filtering, newest-first pages of 20,
  and cursors bound to the month, filters, and archive content snapshot.
- Async HTTPX adapter with a shared Redis request lock/cooldown, coalesced cache
  misses, identifying operator-configured User-Agent, conditional ETag and
  Last-Modified requests, 304 handling, provider cache directives, Age, explicit
  stale fallback, and up to three 429 retries with Retry-After or jittered backoff.
- Five-second connect and 20-second response budgets inside a 90-second total
  budget including limiter waiting/retries. Requests are spaced at least one
  second apart; the Redis lease is 100 seconds. Temporary busy/timeout/rate-limit,
  missing player/month, malformed data, and import failures have typed errors.
- Streaming bounds: 50 MiB monthly JSON, 1 MiB archive index. Identity encoding
  is requested, and unexpected compression is rejected before consuming its body.
  All redirects are rejected, including same-host redirects; returned archive and
  source URLs are validated and never fetched as arbitrary URLs.
- Strict PGN lexical/completion checks plus python-chess parser error, setup,
  position and main-line legality validation; 1 MiB UTF-8 and 300-ply limits.
  Results are cross-checked against provider metadata and automatic terminal
  outcomes. Setup FEN, full SAN/UCI/FEN history, and original PGN are preserved.
- SQLAlchemy/PostgreSQL canonical game identity, PGN hash/version and atomic
  idempotent import. Row locks serialize versions and reject source updates that
  race validation. Alembic upgrade/rollback, Compose startup migration, and local
  migration/recovery instructions are included.
- Strict typed frontend API decoding, request cancellation and stale-response
  suppression; search/month/filter/list/import and distinct failure/empty states.
  Freshness and stale cache are visible. Imported games expose a validated move
  list; board/replay controls remain Sprint 2.
- Generated OpenAPI/TypeScript contracts. HTTPX becomes a runtime dependency;
  SQLAlchemy and Alembic add the PRD's selected persistence/migration boundary.
  Versions are locked in `uv.lock`; direct licenses are in the notices file.

## Observations and limits

- Live lookup requires an operator's real contact in `CHESS_PUBAPI_USER_AGENT`.
  No contact was invented and no live upstream smoke is claimed. The current
  username contract is 3–25 ASCII letters/digits/underscores/hyphens after trim.
- Source caches retain entries at most seven days, honor no-store/private, and
  never use no-cache/must-revalidate entries as stale fallback. Freshness uses
  max-age less Age, capped to 24 hours; absent max-age triggers revalidation.
  Retry-After cooldown is retained even when longer than a day. Archive changes invalidate cursors;
  users restart the selected month's list. Opponent matching is exact.
- Unexpected compression, redirects, invalid monthly metadata, and zero-move
  PGNs are rejected explicitly. Malformed monthly metadata rejects the response
  instead of silently omitting records. An `available` list entry still requires
  full PGN validation when opened; parser failures are then shown distinctly.
- Canonical versions are keyed by normalized source URL (deterministic opaque
  UUID) and PGN content hash. Metadata-only provider edits do not create a new
  canonical version. Pending sources and canonical games are persisted; automatic
  retention/purge, accounts, quotas and analysis lifecycles remain later work.
- Validation and synchronous database calls run in threads; HTTP remains async.
  The total provider deadline does not include subsequent import/database work;
  database connects/statements/pool waits are independently bounded.
- Initial test failures came from HTTPX test `params=` replacing an existing
  query string and a random fixture ID accidentally inflating the timestamp.
  Both fixtures were corrected without changing assertions or product limits.
  The first browser attempt hit sandbox restrictions, then an existing app port;
  the browser server now uses its own port. Final review removed a 24-hour
  Retry-After cap; a two-day cooldown now has explicit regression coverage.
  No test was skipped or suppressed.
- Existing Starlette TestClient and python-chess/Python 3.14 deprecation warnings
  are retained. No mandatory function-length exceptions.

## Setup follow-up

A local setup report exposed ambiguous template instructions: editing
`.env.example` alone left the API's User-Agent unset because `.env` did not exist.
`make up` itself succeeded in the reproduction, but the runtime configuration
assertion failed with `Live lookup configured: False`. Creating the ignored `.env`
from the operator's edited template and rerunning `make up` produced a healthy
stack and `Live lookup configured: True` from the same assertion.

README now explicitly separates copying the template from editing the active
configuration. The operator's template edit was preserved and excluded from the
documentation commit; no contact value was printed or committed. No application
source changed, no additional unit test was needed for this configuration/docs
correction, and no live upstream request or new aggregate test run is claimed.
Relative documentation links and `git diff --check` passed for the correction.
