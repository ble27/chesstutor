### Label policy v2 and specific coach notes (2026-11-09)

Review feedback: row 4 (giving up the center) and row 26 (ignoring a free pawn) were
labelled Blunder; and notes were generic ("throws away a large part of your advantage",
"kept your position strong"). Changes, tests written first:

- **Blunder (policy v2):** `L >= 0.20` is a Blunder only if the engine's played line
  loses at least 3 material points against the best line (final recapturable capture
  ignored) or the played line is mated; otherwise Mistake. Implemented in
  `classification/cost.py` and `classify_move(tactical=...)`; `None` keeps the plain
  band for spec-level callers. The version is now `v2` end to end (labels, badge
  proofs, stored-job compatibility, web validators), so v1 analyses recompute.
- **Miss:** also awarded when the engine's best move captures an undefended piece
  (`tactics.free_capture`), `L >= 0.10`, and the move abandons it. Same verification
  budget and proof type (`material_win`).
- **Coach notes:** `coaching/motifs.py` proves a reason from the board: mate, free
  capture, capture, skewer, pin, fork, discovered attack or check, check, rescued
  piece, new threat, open file, castling, center pawn, development. Flaw notes name what
  the opponent's reply in the engine line allows (mate, lost piece, fork, skewer, pin,
  discovered attack/check, the center, a weakened king, or the replying piece), else
  the older undefended-piece or general text. Great/Brilliant/Miss notes name the
  proven idea; a Brilliant note never presents a plain capture as the idea. Pawn and
  king replies are not named as causes. Tests: `test_blunder_policy.py`,
  `test_motifs.py`, `test_lesson_reasons.py`, plus miss cases in
  `test_badge_verification.py`.
- Checks run: Python unit 449 passed / 43 inherited S7 failures; web unit 164 passed /
  23 inherited S6 failures; ruff, mypy, function lengths, contracts regenerated.
  **Not run:** integration and e2e (Docker daemon unavailable in this session).
  `make check` currently fails Prettier on another contributor's uncommitted
  `features/library` files, not on files from this change.
- Limits: the "weakened king" and "center" causes are heuristics keyed to the engine's
  reply; the 3-point blunder threshold is a product choice to calibrate on annotated
  fixtures; the 8-game sample below is engine-timing dependent and not reproducible
  move for move.

### Pawn-swing bands, policy v3 (2026-11-11)

Review feedback on rows 7 and 26 of the v2 sheet. Stockfish 19 (3 s, White POV):

- Row 7 (Black `Nxd4`): `cxd4` -2.50, `Nxd4` -0.99. The played knight won the same bishop,
  so the "missed chance" note was false, and a 1.5-pawn gap with Black still ahead is not a
  hand-over of the advantage.
- Row 26 (White `Bd2`): +0.53 against +1.01 (`f4`) and +0.99 (`Nd5`), a 0.5-pawn gap with
  White still better. The WDL curve stretched it to a 21% loss and a Mistake.

Changes (tests first, `test_swing_policy.py` and updates to `test_blunder_policy.py`,
`test_badge_verification.py`): labels follow pawn-swing bands (0.5 inaccuracy, 1.0
mistake, 2.0 blunder), tempered by the WDL band (the less severe wins); a Blunder also
needs lost material, a mate allowed or missed, or a drawn/winning position turned losing;
winning the same material by another route is at most an Inaccuracy; a free capture the
played move already makes is not a Miss. Version is `v3` everywhere (PRD section 6 table
updated). Checks: Python unit 479 passed / 43 inherited S7 failures; web unit 183 passed
/ 23 inherited S6 failures; ruff, mypy, function lengths, contracts regenerated.
Integration and e2e not run (Docker unavailable).

Limits: swing bands and the -0.5/-1.5 flip thresholds are product choices to calibrate;
a Blunder justified by a flip or mate can still be explained by a smaller hanging pawn
(the note names a verified fact, not necessarily the largest one); sampled games vary
with engine timing, so rows 7 and 26 are covered by regression tests, not by the sheet.
